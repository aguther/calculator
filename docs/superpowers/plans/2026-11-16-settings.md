# Settings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Implement the approved settings preview, meaningful shortcut help and tactile buttons.
**Architecture:** Keep persistent preferences in CalculatorApp. Add transient SettingsTab state and isolate settings rendering in a module. Share a painted animated button between calculator and settings, preserving stable interaction rectangles.
**Tech Stack:** Rust, egui/eframe 0.33.3; existing browser tests.
**Spec:** docs/superpowers/specs/2026-11-16-settings-design.md

## Global Constraints
- Preserve saved data, existing palettes, switches and touch release-order behavior.
- F2/F3 act only outside settings; no deployment.

## Review Focus
- Small 320px screens and short landscape windows: header/footer remain accessible.
- Keyboard focus must remain visible despite removal of active white outlines.
- Touch cancellation and multiple contacts must not commit unintended keys.
- Switching tabs does not save transient UI state or change preferences.
- Diagnostic clipboard contains the full report rather than only visible summary.
